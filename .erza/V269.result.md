## Holes found & fixed (commit `198fe71`)
1. **Widget keyboard/focus accessibility** (the ironic gap — an a11y widget that wasn't fully keyboard-accessible). The panel used `role="dialog"` but: no Escape-to-close, focus never moved into the panel on open, focus never returned to the trigger on close, and the trigger had no `aria-controls`. Fixed:
   - Escape closes the panel and returns focus to the trigger button.
   - Focus moves to the close button when the panel opens.
   - Trigger gains `aria-controls="a11y-panel"`; panel gains `id="a11y-panel"` and `aria-modal="false"` (correct semantics for a non-modal settings popover — no focus trap, so no keyboard-trap risk).
2. **High-contrast accent contrast.** `--color-brand-forest` (#7C5CFF violet, ~3.9:1 on white) was not overridden in HC mode, so the statement link, focus rings, and CTAs could fall below AA in the very mode meant to raise contrast. Fixed: override to `#0000CC` (~13:1) inside `.a11y-high-contrast` (+ `-deep` to `#000099`). Verified in built CSS (minified to `#00c`).

## Noted, intentionally NOT changed (with justification)
- **FOUC for returning users with saved a11y prefs** (classes applied in `useEffect`, so a flash of default styling on load). This is a **pre-existing, codebase-wide pattern** — `lib/i18n.tsx` applies `dir`/`lang` the same way (Hebrew users already get an LTR→RTL flash), and `<html suppressHydrationWarning>` reflects that accepted tradeoff. Introducing a bespoke no-flash inline script only for a11y classes would be inconsistent and a larger architectural change than warranted. Left as-is; flagged here for a possible future site-wide no-flash pass.
- **`set-state-in-effect` lint error** in `AccessibilityWidget.tsx:47` (reading `localStorage` on mount). This is a legitimate SSR-safe pattern and **matches the existing unsuppressed occurrences** in `lib/i18n.tsx:420` and `app/auth/confirm/page.tsx`. It does not block `next build` (Next 16 doesn't run ESLint in build). Left consistent with codebase convention rather than adding a one-off suppression.
- **Anti-spam / cookie / most privacy items** — confirmed N/A: no forms, no email/SMS-sending, no cookies/analytics in this repo (matches T269's scoping).
