# T269 — healthy-web Israeli compliance fixes (5)

**Status:** DONE (implemented, built, smoke-tested locally). Not pushed (per protocol — local commit only).

## Scope decision

Audited the repo against `compliance/israeli-business-compliance-checklist.pdf` (3 laws: accessibility IS 5568/AA, anti-spam Amendment 40, privacy Amendment 13). Findings:

- **Anti-spam (Amendment 40) and most privacy sub-items (Amendment 13) are N/A for this repo**: healthy-web is a marketing site for the "Healthy Circle" iOS/macOS app with **no forms, no email/SMS-sending code, no analytics/tracking pixels, no cookies anywhere in this codebase**. There is nothing to attach a marketing-consent checkbox or unsubscribe link to. Privacy policy already exists (`app/privacy`, `content/privacy.*.md`) with detailed data listing and security measures — no gap there.
- **All 5 real, actionable gaps were in the accessibility category** (IS 5568/AA), so the "5 fixes" were scoped there:

1. **Accessibility statement page** — new `app/accessibility/page.tsx` + `content/accessibility.{en,he}.md`, following the existing `privacy`/`terms` page pattern (`LegalPage`, `loadDoc`). Names Erez Cohen as accessibility coordinator with the existing support email, states partial conformance to IS 5568/AA, lists what's implemented and known limitations. Linked from `Footer.tsx` and added to `app/sitemap.ts`.
2. **Accessibility widget** — new `components/AccessibilityWidget.tsx`, floating button (bottom corner, RTL-aware) with: text-size increase/decrease/reset (3 steps), high-contrast mode toggle, stop-animations toggle, and a link to the statement page. Persists to `localStorage` (`healthy-a11y` key), applies via `<html>` classes, mounted globally in `app/layout.tsx`. Supporting CSS added to `app/globals.css`.
3. **Alt text fix** — `components/Hero.tsx` had two decorative-looking but actually-meaningful phone screenshots with `alt=""`. Replaced with localized captions matching `Showcase.tsx` (`t('cap2')`, `t('cap4')`).
4. **Color contrast fix** — `--color-text-muted` in `app/globals.css` was `#837E94` on `#FBFAFF` (~3.76:1, fails AA's 4.5:1 minimum for normal text). Changed to `#726D87` (~4.76:1, verified by hand via WCAG relative-luminance formula).
5. **Keyboard navigation** — new `components/SkipLink.tsx` ("Skip to main content" / "דלג לתוכן הראשי"), mounted in `app/layout.tsx` before the header; `<main>` given `id="main-content"` + `tabIndex={-1}`.

All new UI strings added bilingually to `lib/i18n.tsx` (`navAccessibility`, `skipToContent`, `a11y*` keys).

## Verification performed

- `npm run build` — compiles clean, `/accessibility` appears as a new static route.
- `npm run dev` + `curl` smoke test: `/accessibility` returns 200 with real statement content; homepage HTML contains the skip-link text and `id="main-content"`.
- Manual WCAG contrast-ratio calculation for the new `--color-text-muted` value (~4.76:1, passes).
- Did **not** do full manual screen-reader / keyboard-trap testing across every page — the accessibility statement itself discloses this ("full manual testing... is ongoing") rather than overclaiming full conformance, which is the legally correct approach for a statement of partial conformance.

- No iOS/macOS app changes, no App Store Connect actions (this repo is web-only; Apple submission rule N/A here).
- No OTA/EAS channel changes (N/A — this is a Next.js website, not the Expo app).

- Cookie notice — no cookies/tracking found in this repo; if Vercel Analytics or similar is added later at the hosting/deployment layer (outside this codebase), revisit.
